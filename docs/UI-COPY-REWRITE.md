# leeway 文案重写对照表

> 范围：窗口界面（`internal/gui`）全部菜单与功能文案 + `leeway help` 系列帮助文本。
> 规则：功能含义不变；名称 2–4 字；名称 + 一句描述 ≤20 字；长段落压到两句内、能扫读；
> 一律用日常说法，不用术语。
> 本轮**已全部落地**：窗口与 CLI 的文案改名见提交 `906cb5a`（界面与帮助文案）、`e608c27`
> （文档跟着换名）、`6d70340`（用户可见英文清零）；落地记录见 §7、§8，没做的集中在 §7.4。
>
> **已作废的一节**：下表里 `trend.go:134 / 248 / 275` 那三条「用满预测」文案，对应的功能已经按
> 要求从界面移除（见 `docs/GUI.md` 的「不做用满预测」），不要再照表把它们加回来。

判断依据：
- 《Don't Make Me Think》——用户不读说明，只扫一眼；每一处文案要自己回答「这是什么 / 点了会怎样」。
- 《写给大家看的设计书》——对比、重复、对齐、亲密性：同一个东西只有一个名字，同一类控件只有一种句式。
- 苹果文案的克制：短句、具体动词、不用感叹号、不解释自己、不甩术语。

## 0. 先说结论：九个系统性问题

不是零散错字，是六个反复出现的模式。改文案时按这六条走，比逐条抠字更有效。

### 问题 1：术语密度过高，用户要先学一套词才能用

现在界面上真实出现的术语：provider、凭据、探测、额度窗口、会话、cookie、key、token、
HOME、DSH、CLI、点阵、快照、限流、HTTP 超时、JWT、隔离目录。

最刺眼的一条在「关于 → 探测方式」：

> leeway 只读各 provider 的用量接口：用你自己的 key、cookie，或官方 CLI 已经登录好的会话。
> 凭据不进日志、不进 JSON 输出；密钥只写进你自己的 config.json。

两句话 100 个字符，塞了 10 个术语。它想说的其实只有一句：**「leeway 只看不改：用你已有的登录信息去问还剩多少额度。」**

### 问题 2：一个东西好几个名字

| 同一个东西 | 现在有几种叫法 |
| --- | --- |
| 那 7 家 AI 服务 | provider / 家 / 服务 / 各家 / 各 provider |
| 本机的官方工具 | 官方 CLI / 官方客户端 / 本机官方客户端 / 本机 / 本机其它地方 |
| 登录信息（总称） | 凭据 / 登录态 / 会话 / 令牌 |
| └ 其中一类：API 密钥 | key / API key / 密钥 |
| └ 其中一类：浏览器登录状态 | cookie / Cookie header |
| └ 其中一类：登录文件 | 会话文件 |
| 一次查询 | 探测 / 查询 / 刷新 / 读取 / 重新解析 |
| 复制那份数据 | 复制 JSON（文件菜单）/ 复制当前 JSON（账号菜单、操作菜单、矩阵菜单） |
| 设置入口 | 设置…（菜单）/ 设置（标题栏） |
| 没有可用的服务商 | 没有启用的 provider（标题栏）/ 配置过的 provider 会出现在这里（侧栏） |
| 查询失败 | 失败 / 探测失败 / 这次探测没有答上来 / 这个账号这次没有答上来 / 这一家这次没有答上来 |
| 无数据 | 未报告 / — / 尚未探测 / 还没有历史点 / 没有可用的 provider / provider 没有报告任何额度窗口 |

### 问题 3：中英文混排，同一个界面里两套语言

- 侧栏和标签是中文，**额度卡片的名字却是英文**：`Balance`、`Weekly`、`Included`、`Credits`、
  `On-demand`、`Renewal`（`internal/gui/format.go:249`）。于是出现 `Balance 余额 ¥12.50` 这种
  中英各说一遍的重复。
- 设置页三个标签：`通用` / `Provider` / `数据`——一个英文夹在中间。
- 确认框标题：`退出 kimi 账号 work?`——品牌名 + 中文 + 半角问号。
- 关于页：`界面 go go1.27.2`——「go」出现了两次。
- **最显眼的一处：整个菜单栏两种语言。** 只有「文件」及其子项是我们写的中文；
  应用菜单、`Edit`、`Window` 和 `Close Window` 全部由 MyGo 的角色按英文生成
  （`view.go:95 / 102 / 104 / 105`）。用户打开菜单栏看到的是 `Edit`、`Window`、`Close Window`
  和「文件」并列。

### 问题 4：高危操作的名字看不出后果

「让本机用它」是本产品唯一会**改写你本机官方工具登录状态**的操作
（cursor 的钥匙串项、`state.vscdb`、`~/.cursor/auth.json`；grok 的 `~/.grok/auth.json`；
kimi 的 `kimi-code.json`），而它的名字读起来像一句无关紧要的客套话。
同一个概念在别处又叫「写回官方」「切号」。

改名不是改一处：这个名字被 `page_provider.go:92` 的说明句和 `prompt.go:267` 的确认标题
直接引用，是**三处联动**。

### 问题 5：说明文字写成了一整段，扫不了

- 首次使用引导页开头是一句 50 字符（29 个汉字）的长句，还带一个冒号从句。
- 退出登录确认框正文是一句 81 字符的括号套括号，用户点「退出登录」前根本读不完。
- 设置页每条下面都是一句技术解释（`等价于 LEEWAY_TIMEOUT`）。

### 问题 6：状态词不统一，同一个状态在不同地方叫法不同

`正常 / 失败 / 未配置 / 已移除 / 注意 / 待刷新` 是一套，但同一个意思在正文里又写成
「不参与探测」「不会参与探测」「已在设置里停用」「已停用，不参与探测」四种。
更细的账：**「查询失败」有 5 种叫法，「无数据」有 6–7 种叫法**（见问题 2 的表），
而且矩阵页的 `—` 同时表示「没有这一项」和「有这一项但没数字」两种情况。

（顺带：「注意」这个状态疑似死文案，见问题 9。）

### 问题 7：错误只说「错了」，不说「怎么办」

CLI 侧 45 条错误逐条看下来：说清原因的 38 条，**给出可照抄下一步的只有 19 条，完全没给的 22 条**。
`leeway use` 的六条失败里只有两条给了能直接敲的命令。而且前缀中英混排——
`usage:` / `config:` / `save key:` / `read key:` / `write session:` 跟中文正文挤在一行，
同一类错误看起来不像一类。

窗口侧同理：`探测失败` 只报结果，用户要自己猜是没配、过期、还是网络问题。

### 问题 8：最该说清的地方偏偏没说清（三个具体漏洞）

这三条不是文风问题，是**信息缺失**，都经代码确认：

1. **切换账号的确认框不提「必须先退出 Cursor」。**
   `switcher.CheckCursorIDE()` 会在 Cursor 运行时直接阻断（`ops.go:620`），
   但确认框（`prompt.go:265–273`）一个字都没提。用户点完才知道失败。
2. **不可逆的警告只出现在成功之后。**
   cursor 原登录读不出来时，切换是**不可逆**的；而唯一的警告
   （`app.go:664`「原登录不在 leeway 台账里，切走之后只剩目标号」）是一条
   **成功之后**的 toast。等用户看到，已经切完了。
3. **唯一讲清「让本机用它」作用域的说明，大多数人看不到。**
   `page_provider.go:92` 那句话只在账号数 > 1 时渲染；单账号（最常见的情况）
   永远读不到它。

另外两处字面自相矛盾：

- `page_start.go:17` 说「leeway 不替你登录」，同一张卡片每一行的按钮却写着「用官方 CLI 登录」。
- `view.go:548`「退出登录」实际只删 leeway 自己的副本、不动官方工具，
  而它旁边就是「删除 API key」——两个标签并排，用户会以为两个都动官方工具。

### 问题 9：有一批文案是「死」的——写了，但用户永远看不到

清点时发现的，不是文风问题，是**维护负担**：

- `prompt.go:72 / 83 / 97 / 105 / 127 / 136` 六条弹窗 `title` **当前根本不显示**：
  `promptview.go:101–109` 的副标题优先用服务商显示名，把 title 盖掉了。
  这六条既没有测试断言，也没有别的读取点。
- `format.go:175` 的「注意」（warn）**疑似死文案**：
  服务商和账号的状态只会是 `ok` / `error` / `not_configured` / `disabled`
  （`app.go:442–449`、`fetch.go:209–301`），找不到写 `warn` 的路径。
- **「已用尽 / 100%」这个状态在整个界面里没有名字**，只有数字。
  用户看到 100% 时，界面不会告诉他「已经用完了」。

**建议**：改文案时顺手确认这些是否该留。留就补测试，不留就删——
死文案会让下一次改文案的人以为它有用。

## 1. 术语对照表（改名前请先确认）

判断标准：一个从没读过 README、只装了某个 AI 编程工具的人，能不能一眼看懂。

### A. 必换

| 现在叫 | 出现在哪 | 建议叫 | 为什么 |
| --- | --- | --- | --- |
| provider | 侧栏、标题栏、设置页、几乎所有页面 | **服务商** | 用户想的是「我订的那家 AI」，不是编程概念 |
| 凭据 | 详情页「凭据位置」、引导页「已找到凭据」 | **登录信息** | 「凭据」是安全行业词，读起来像要交密码 |
| 探测 / 探测中 / 探测失败 | 标题栏、设置页、错误行 | **查询 / 正在查询 / 查询失败** | 「探测」像扫描仪，用户只是想知道还剩多少 |
| 额度窗口 | 「没有报告任何额度窗口」 | **额度周期** | window 是 API 词，用户想的是「这轮什么时候重置」 |
| 会话 / 会话文件 | 登录弹窗、切号确认框、CLI 错误 | **登录文件**（文件）/ **登录信息**（状态） | 「会话」在中文里首先想到聊天窗口 |
| cookie / Cookie header | 导入弹窗、缓存清理、错误提示 | **浏览器登录状态** | 用户不需要知道 cookie 这个词 |
| key / API key | 登录弹窗、删除确认框 | **API 密钥** | 统一中文，别让 key 和「密钥」并存 |
| token / 令牌 | CLI 错误「官方 CLI 没写出令牌」 | **登录信息** | 一个东西只给一个名字 |
| 切号 | 详情页说明、CLI 帮助 | **切换账号** | 「切号」是圈内缩写 |
| 让本机用它 | 账号菜单（最高危操作） | **启用**（已定） | 服务商开关改叫「添加/移除」，把这个词让给了账号动作（见 5.1.1） |
| 私有 HOME | 删除确认框 | **leeway 自己的登录目录** | HOME 是 shell 变量 |
| 点阵 | 历史页说明、CLI 帮助 | **走势图** | 「点阵」是打印机名词 |
| 快照 | 导入说明、CLI 错误 | **备份** | 「快照」是运维词 |
| 设备码 JWT / 设备码会话 | CLI 错误 | **一次性登录码** | 同上 |
| 限流 | 「provider 报告已限流」 | **请求太频繁** | 说人话，并说清下一步 |
| 家 / 号 | CLI 帮助（「要看的家和号」） | **服务商 / 账号** | 口语缩写，正式文案里不该出现 |
| 增量 / 点阵 | `usage` 帮助 | **相比上次的变化 / 走势图** | 同上 |
| DSH | 只出现在内部，界面上别暴露 | **leeway 自己保存的配置** | 用户不认识这个缩写 |

### B. 保留（已经是日常词，不必为改而改）

| 词 | 判断 |
| --- | --- |
| 额度 | 中文已通用，比「配额」好 |
| 用量 | 保留 |
| 重置 | 保留 |
| 刷新 | 保留 |
| 账号 | 保留 |
| 添加 / 移除 | **服务商开关改叫这两个词**（已定）；「启用」让给账号动作 |
| 总览 / 历史 / 关于 / 设置 | 保留 |
| 官方工具 | 保留，但**必须统一**（现在是「官方 CLI / 官方客户端」混用） |

### C. 一个东西只留一个名字（强制统一）

| 统一成 | 替换掉 |
| --- | --- |
| **服务商** | provider、家、服务、各家 |
| **官方工具** | 官方 CLI、官方客户端、本机官方客户端、本机 |
| **登录信息**（总称） | 凭据、登录态、会话、令牌 |
| ├ **API 密钥** | key、API key、密钥 |
| ├ **浏览器登录状态** | cookie、Cookie header |
| └ **登录文件** | 会话文件 |
| **查询** | 探测、读取、重新解析 |
| **本地登录状态** | 缓存、cookie 缓存 |
| **已移除** | 不参与探测、不会参与探测、已在设置里停用、已停用 |

关键点：**「登录信息」是总称，下面三种东西各有自己的名字**——
现在的毛病是拿总称（凭据）当小名用，又拿小名（key / cookie / 会话）当总称用，
所以同一句话里会同时出现「凭据、cookie 与配置里的 key」三个词指同一件事。

## 2. 跨界面统一建议

1. **额度卡片名保持现状（已定）**：`Balance` / `Weekly` / `Included` / `Credits` /
   `On-demand` / `Renewal` 不改，继续显示服务商原文。`format.go:249` 不动。
2. **设置页三个标签统一中文**：`通用` / `服务商` / `数据`。
3. **状态词收敛成一套**：`正常` / `失败` / `未配置` / `已移除`，
   正文里不再写第二套说法。「注意」（warn）疑似死文案，先确认再决定留不留（见问题 9）。
4. **统一用「刷新」（已定）**：重新查询现在有五个名字——
   `刷新` / `刷新看看` / `重新读取` / `立刻刷新` / `重试`，**全部改成「刷新」**。
   不同动作（`详情`、`去设置`）保留各自说法，但要成体系：**动词 + 对象**。
5. **高危操作加一句后果说明**，且**只在高危处加**（普通操作不加，避免训练用户点掉确认框）。
6. **确认框按钮的颜色要分级**：现在四个框的主按钮一律危险红，连可逆的「启用」「重新读取」也是红的。
   红按钮一多，用户就学不会哪个真的危险（见 4.9.1）。
7. **名称一律 2–4 字**：现在超标的至少有「打开配置目录」（6 字，且名字不诚实，见 5.2 第 17 条）、
   「复制当前 JSON」（6 字）、「退出登录」（4 字但含义错）。
8. **三个动作各归一个词（已定）**：服务商开关用 **添加 / 移除**，账号动作「让本机用它」用 **启用**，
   `已停用` 状态改 **已移除**。详见 5.1.1。

#### 备份核查：原表那句「会被备份」是错的

我原先写「会先把官方工具当前的登录备份成 leeway 账号」。实施时逐行核实，
**只有 cursor 会备份，而且不保证成功；grok / kimi 是直接覆盖，旧登录不留副本。**

| 服务商 | 会不会备份 | 证据 |
| --- | --- | --- |
| cursor | 会，best-effort | `internal/gui/ops.go:627` 先调 `switcher.SnapshotCursorIfNeeded`（实现 `internal/switcher/switcher.go:288–320`）；但 `switcher.go:347–348`（同名账号里已是另一个 token）和 `357–363`（只有 access token、没有 refresh token）会返回「没保住」 |
| grok | **不会** | `ops.go:689–711` 只调 `ApplyGrok`；`mergeGrokAuth`（`switcher.go:430–437`）把官方 `https://auth.x.ai::*` 条目**直接 delete 再覆盖** |
| kimi | **不会** | `ops.go:752` 直接 `writeFileAtomic` 覆盖 `~/.kimi-code/credentials/kimi-code.json` |

旁证：`SnapshotCursorIfNeeded` 全仓库只有两个非测试调用点（`internal/gui/ops.go:627`、
`internal/cli/cli.go:382`），**都是 cursor**。

所以确认框正文只描述确实发生的事：
**「leeway 会把该账号的登录文件写给官方工具。官方工具当前的登录会被覆盖。」**
对三家都成立，而且比「会被备份」更该让用户看到——grok / kimi 用户不会以为有后悔药。

#### 4.10.1 错误文案的三个硬伤（改文案前必须先定这三条）

这三条不是措辞问题，是**用户拿不到信息**，都经代码确认：

1. **库的英文错误被丢掉，用户只剩四个字。**
   `app.go:656`（同型还有 `682 / 696 / 711 / 724`）写的是
   `a.toast, _ = failureText("切换失败", err.Error())`——第二个返回值被 `_` 扔了。
   当底层错误是英文（库错误）时，用户只看到「切换失败」，**原因和下一步全没有**，
   连页面错误行那样的 tooltip 都没有。
   **建议**：不要丢，把详情接进 tooltip；英文原文进日志。

2. **有一处错误行绕过了统一的错误规则。**
   `promptview.go:58` 是 `errorLine(c, p, a.prompt.err, "")`——detail 传了空串，
   于是整条绕开了 `view.go:434` 的 `failureText` 规则。
   结果是 `ops.go` 原样返回的库错误（`os.ReadFile`、`writeFileAtomic`、`config.Load`，
   **常带真实绝对路径**）以英文红字直接上屏。
   而 `view.go:441–445` 的注释明确写着「库自己的错误文本不上屏」——代码和注释相反。
   **建议**：这一处也走 `failureText`。

3. **两条错误会把真实路径打进吐司。**
   `ops.go:724`「kimi 账号 %q 的会话文件不在 %s」和 `ops.go:856`「拒绝删除 %s：不在 leeway 会话目录里」
   里的 `%s` 是**真实绝对路径**，会进吐司。用户截图或录屏时会把用户名一起带出去。
   **建议**：路径改成 `~/…` 形式，或只说文件名。

### 8.3 `leeway status`：表头中文化，撞上 `text/tabwriter` 的真问题

表头改成 `服务商 / 账号 / 登录信息 / 状态 / 过期时间`，值也给了中文（`配置里的 API 密钥` /
`私有登录文件` / `正常` / `今天 16:31 过期`）。

改表头时发现一个真问题：原来用 `text/tabwriter` 排版，**它按 rune 数对齐，而 CJK 字符占两个
终端列**，于是中文单元格和它的表头必然错位（表头起点在第 16 列、数据在第 13 列）。
往单元格里补 ASCII 空格**修不好**——空格给 rune 数和显示宽度各加 1，差值恒定；补 U+3000
能修但要塞不可见字符。所以换成了自己按 `displayWidth` 排版（`writeStatusTable`），
现在表头与数据的起点都在显示列 `[0, 13, 53, 72, 78]`，且没有行尾空格。
`internal/render` 用的是纯缩进、没有 tabwriter，所以那边不受影响。
