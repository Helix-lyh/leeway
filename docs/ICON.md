# 图标（`resources/icon.png`）

> 这份文档记的是 leeway 主图标这一轮从概念到落地的完整过程，重点是**方法**：
> 哪些决定是算术推出来的、哪些是试错试出来的、哪些错是我自己犯的。
> 生成器在 [`resources/icon.py`](../resources/icon.py)，provider 小图标在
> [`resources/provider-icons.py`](../resources/provider-icons.py)。
>
> 过程件（多轮候选、brief、校验脚本）都在 `build/icon-work/`，而 `/build/` 是 gitignore 的，
> 所以**这份文档要能独立看懂**，不能指望读者去翻那些图。

## 1. 图形在说什么

一笔毛笔，盘成螺旋；笔身是已经用掉的额度，笔锋散开的那几根是还没花的。

为什么是螺旋而不是进度条。进度条是一根线，而 leeway 的图标如果画成进度条，就是在**复刻自己
窗口里的一个 UI 组件**——Apple 的 HIG 恰好明确禁止这个（"prefer illustrations to photos and
**avoid replicating UI components**"）。第一版做了四个进度条方案，全被这条规则否掉，不是品味问题，
是规则问题。把线盘起来则说出了进度条说不出的一半：**额度会转回来，会重置，会周期**——这正是
leeway 探测的核心。而进度条本身就是一根线，所以螺旋不是换了个题材，是同一个元素做拓扑变换。

「尾」这个谐音是用户提的，它和产品语义严丝合缝：尾巴的长度＝还没被花掉的长度。

## 2. macOS 图标的硬契约

- 1024×1024 方图，**超椭圆本体直接烘进像素**，四角透明留白。Apple 的网格是 824 的 squircle
  居中放在 1024 里，角指数 **n=5**（不是圆角矩形）。
- `mygo` 的 `pngToICNS`（`cmd/mygo/icon.go`）只是把图缩到 icns 的各档
  （`icp4 16 / icp5 32 / ic12 64 / ic07 128 / ic13 256 / ic14 512 / ic10 1024`），
  **它不做任何遮罩**。所以 squircle 必须由生成器自己烘进去。
- 超椭圆的半径**不是常数**：轴线上 412px，45° 方向反而涨到 **507px**（n=5 让它比圆更"方"）。
  约束取最紧的那处，也就是**轴线上的 412**。

## 3. 半径预算是算术，不是口味

笔身能做多粗，是被半径预算锁死的，先解方程再画，能省掉一整轮无用候选。

一笔螺旋的外缘半径 ≈ `R1 + WIDTH/2`，必须留在 412 以内（实用值取 **380**，留出余量）。
圈数 N 决定了相邻两圈的间距 `pitch = (R1 − R0)/N`，而 `gap = pitch − WIDTH` 是两圈之间能看见的缝。
把这三条联立，令中心孔半径 h≈30、要求 gap ≥ 54：

```
WIDTH ≤ (350 − 54N) / (1 + N)
```

| 圈数 N | 笔身上限 | 占画布 |
|---|---|---|
| 1.0 | 148 | 14.5% |
| 1.1 | 145 | 14.2% |
| 1.2 | 130 | 12.7% |
| 1.4 | 114 | 11.2% |
| 1.6 | 101 | 9.9% |

**结论很反直觉但很重要：想画粗，就得少绕圈。** 一次把圈数从 1.6 降到 1.1，笔身就允许从 101 涨到
145——粗了 44%。最终取 **N=1.10 / WIDTH=145**：1.6 圈在 16px 会糊成一朵实心玫瑰，而粗笔身换来的是
小尺寸下可读的轮廓，这笔交换划算。

同一轮还量出一个更基础的问题：第一版图形的最大半径只有 **265px**，只占可用空间（412）的 64%——
它不只是线细，是**整个图形就小**。放大到 380 之后，笔身的绝对宽度从 132 涨到 145，而相对画布的
占比提升更多。

## 4. 用代码画：`resources/icon.py`

### 4.1 线宽必须画成多边形，不能用 `ImageDraw.line`

一开始用 `ImageDraw.line` 画一条 900 点的折线、宽度 384px。它在 4096 画布上每段只有 12px 长，
于是线段互相自交、填充出**空洞**，底下那层浅紫透上来，看起来像放射状条纹。

正解是把笔触渲染成**两条偏移曲线围成的精确闭合多边形**（`band()`）：外缘点 + 端头半圆 + 内缘反向 +
起始半圆。数学上干净，没有洞。顺带一提，那次的"放射条纹"用户反而觉得像毛发、要求保留——但它
是缺陷不是设计，所以保留的是它的**观感**（后来的飞白纹理），不是它的成因。

### 4.2 端头半圆的圆心角（一个真 bug）

`band()` 的端头要补一个半圆把内外两条边封上。第一版写的是：

```python
arc(x, y, h, a + pi/2, a - pi/2)   # 错
```

这是**以 `a` 为中心**的半个圆盘——它连接的是左右两个切线极点，根本没接到内缘和外缘。结果多边形在
端头自我交叠，PIL 按奇偶规则填充，**在每个线头的端部咬掉一个半圆缺口**。用户放大截图圈出来问
"这几个缺口是啥"，我才发现。

正解是从**外缘**（角度 `a`）经切线扫到**内缘**（`a+π`）：

```python
arc(x1, y1, h1, a1, a1 + pi)              # 端头，鼓出去
arc(x0, y0, h0, a0 + pi, a0 + 2*pi)       # 起头，往回鼓
```

`build/icon-work/` 里候选脚本的 `capsule()` 是同一类几何的另一份实现，那里的半圆写法是对的，所以只有
螺旋主体中招——这也说明**同一类几何在两个地方各写一遍，就有一处会错**。

### 4.3 居中要量对东西

`mark()` 只拿**笔身本体**量 ink bbox 来居中。墨点是甩出去的、散毛是拖出来的，把它们算进去，
一个偏远的墨点就能把整个螺旋拽偏。做这个决定的时候正是用户指出"你这个改的位置不居中"之后。

### 4.4 其他

- 4x 超采样（4096 → 1024 LANCZOS），这是边缘干净的主因。
- 盘面是**一条干净的垂直渐变**，没有发光、没有倒角。中途我加过一团左上角的柔光，后来删了——
  那正是我自己批评生成图时用的词"没有动机的柔光"。
- 飞白（`DUTY=0.78`）：笔身由若干根鬃毛并排构成，之间留细缝。大尺寸看得见丝痕，缩到 16px 缝隙
  自然糊成实心调子，两边都不亏。
- 墨点用**固定种子的伪随机**（`INK_SEED`）。图标是构建产物，不能每次生成都不一样。
- 墨点沿**旋转的切线方向**甩出，并且越远越小越散——这是"力量感"的来源，均匀撒开就只是噪点。
- 散毛是**几像素宽**的发丝（2.5–5px，对 145px 的笔身）。做粗了就不再是散毛，而是跟主笔触抢戏的第二笔。

## 5. 用大模型生成：什么时候用，怎么提要求

### 5.1 分工

模型擅长**表面质感**，不擅长**构图、几何、居中、比例**。这一轮的结论是把两边分开：

- **质感**（飞白、散毛、火花般的溅射）交给模型——真实的干笔丝痕手写代码很难做"活"；
- **几何、颜色、盘面、遮罩、居中、缩放**留在代码里。

所以生成的图**只要笔触本身**：纯白笔触 + 纯黑底，方图。盘面由 `icon.py` 提供。

### 5.2 brief 怎么写

- **把"不要什么"写死。** 不点名禁止，模型一定会加：发光、雾、灰阶过渡、笔触背后的卡片/面板、
  暗角、边框、黑底上的噪点。第一轮回来的图带着灰底卡片和一圈压缩晕。
- **要什么就用可判定的语言。** "笔身要粗"没用，写"笔身宽度约为画面宽度的 1/7"、"螺旋外径约为画面的 72%"、
  "整个图形必须落在直径 72% 的中心圆内，四角干净"。能自查的约束才会被遵守。
- **一次只要 2–4 个备选。** 要 12 个的后果是模型把预算烧在数量上，每个都不够改——而且选项太多反而
  挑不出方向。
- **一次只让它干一件事。** 两次让它"重画质感 + 保存到指定路径"，两次都耗尽了轮次、图留在自己的
  session 目录里没保存。让它专心出图，落盘由外面做。
- **给参考图，并且按用途命名。** 用户给的毛笔参考（飞白、墨点）和火花参考（长拖尾）直接决定了成败：
  在给火花图之前，"溅射"一直做成一粒粒圆点，像撒了珠子；给了之后才明白要的是**细长微弯的光丝**。
- **几何参考要标注"只抄形状、别抄风格"。** 不然模型会把平涂的矢量外观一起抄回去。

### 5.3 反复出现的失败模式

| 失败 | 表现 | 对策 |
|---|---|---|
| 太细 | 画成细笔，笔身被拆成并排独立细线 | 明确"一整块实墨，丝痕在内部"；给定量宽度 |
| 太小 | 图形只占画面一半 | 写死"外径约 72%" |
| 太散 | 溅射撒满画面 | 写死"紧贴笔锋，约一个笔身宽以内" |
| 偏 | 重心倒向右上角 | 写死"落在中心 72% 圆内，四角干净" |
| 僵硬 | 粗细均匀的一条带子 | 要求**提按**：起笔细、中段最饱满、收笔甩出 |
| 加料 | 灰底卡片、发光、水印 | 负向清单写死 |

### 5.4 输出契约

要求模型输出**纯白 `#FFFFFF` + 纯黑 `#000000`**，不是审美偏好，是为了后面能直接拿**亮度当遮罩**。
同理要求方图、居中、72% 圆内——都是为了接回代码时少做假设。

## 6. 把模型产物接回代码

（`build/icon-work/compose.py`，这一步是临时的，落地后视情况并进仓库。）

1. **亮度即遮罩**，用**软阈值**（0.30–0.85 的斜坡）而不是硬二值化。干笔处本来就"墨少"，让它透出底色
   才是干笔的样子；硬二值化会把飞白直接砍掉，而那正是请模型来的全部理由。
2. **背景要量出来减掉**。不能假设是 0——模型给的可能是灰卡片。取边框像素的中位数当底色。
3. **阈值要高于 JPEG 振铃。** 模型多半回 JPEG，笔触周围有一圈极淡的压缩晕。阈值压太低会把晕一起提上来，
   结果就是"散"和"灰"。这条是用户说"太散"之后才定位到的。
4. **居中用质心，不是外框。** 图形有尾巴和甩出去的溅射，外框中心离旋转中心很远；按外框居中会把笔身
   推到左下角，看起来像要飞出去（这版被用户否了）。质心法对**开口螺旋**同样成立——螺旋是开口的，
   所以"内圈围出的洞"和外部连通，洪水填充会直接灌进去，那条路走不通。
5. **缩放按遮罩解，不要猜目标半径。** 像素半径这个数对每次生成意义都不同（质心离最远墨点的距离每次
   都不一样）。正解是对每个墨迹像素求它所在角度上超椭圆的半径，取最小的比值——数学上保证不会被切。
   实测三版解得 1.056–1.088。
6. **验证**：合成后逐像素检查有没有墨迹落在 squircle 之外（三版都是 0）。

## 7. 校验工具，以及它们的**局限**

三个工具都在 `build/icon-work/`，都是设计无关的：`eval.py`（16px/32px 覆盖率、盘面平整度、边缘软度）、
`silhouette.py`（丢掉颜色糊成剪影）、`hero.py`（明暗卡片 + 放大到 32/16px）。

**但它们是找缺陷的，不是判品味的。** 两个反例必须记住：

- 拿同一套指标去量 Pulse 的图标（设计标杆），它是 16px 7.8% / 32px 9.5% / 平整度 40.4 / 软边 87.7%——
  **每一项都比我们差**，但人家设计得更好。
- 刻线版（细密丝线）的 16px 覆盖率是 **14.1%**，笔锋版是 **10.5%**——覆盖率更高，但剪影明显更糊。
  **覆盖率 ≠ 可读性。**
- `silhouette.py` 的阈值 120 是按实心图形标定的，对刻线/细笔**会漏检**。刻线版在小尺寸下剪影发白，
  但它的 16px 覆盖率有 19.1%，是能看见的。**不能只凭剪影就断言细笔在 16px 会消失。**

## 8. 教训

1. **先查规则，再谈品味。** 前四个方案死于 HIG 的一条明文禁止，不是死于审美。先读约束能省一整轮。
2. **几何先解算术。** "想粗就少绕圈"这种反直觉结论，画之前算出来，画之后才发现就浪费一轮。
3. **自己会犯自己刚批评过的错。** 我批评生成图"没有动机的柔光"，转头在自己的盘面上加了一团。
   审自己的代码要用审别人的标准。
4. **同一段几何写两遍，必有一处错。** 端头半圆的 bug 就藏在"螺旋主体"和"`capsule`"两份实现之间。
5. **模型的产物要当外部输入对待。** 它给的背景、居中、比例、色值都不能假设，全都要量、要减、要解。
6. **随机必须可复现。** 固定种子，否则图标不是构建产物。
7. **量对东西才算量过。** 居中量错对象（把散毛墨点算进 bbox）比不居中更糟。
8. **一次别要太多备选。** 2–4 个刚好，多了既是浪费也是逃避取舍。
9. **让模型一次只干一件事。** 又要重画又要落盘，两次都耗尽轮次、什么都没存下来。
10. **数值指标只能证伪，不能择优。** 它告诉你哪里坏了，不告诉你哪个美。

## 9. 重做一次的话

```sh
python3 resources/icon.py                 # 生成 resources/icon.png（需要 Pillow）
go run github.com/egoist/mygo/cmd/mygo@v0.3.4 build   # 打 .app / .dmg，顺带出 icns
```

顺序：① 先解半径预算定圈数与笔身 → ② `band()` 画多边形（端头半圆从外缘扫到内缘）→
③ 只量笔身本体居中 → ④ 4x 超采样 → ⑤ 烘 squircle、四角透明 → ⑥ 用剪影测试在 64/32/16 各看一遍，
**并且记住它只证伪不择优**。
