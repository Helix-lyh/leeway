# 图标（`resources/icon.png`）

> 这份文档记的是 leeway 主图标这一轮从概念到落地的完整过程，重点是**方法**：
> 哪些决定是算术推出来的、哪些是试错试出来的、哪些错是我自己犯的。
>
> 产物：生成器 [`resources/icon.py`](../resources/icon.py)，笔触源图
> [`resources/icon-brush.png`](../resources/icon-brush.png)，窗口标题栏的字形
> [`resources/icon-glyph.py`](../resources/icon-glyph.py)，provider 小图标在
> [`resources/provider-icons.py`](../resources/provider-icons.py)。
>
> 过程件（多轮候选、brief、校验脚本）都在 `build/icon-work/`，而 `/build/` 是 gitignore 的，
> 所以**这份文档要能独立看懂**，不能指望读者去翻那些图。

## 1. 图形在说什么

一笔毛笔，盘成螺旋；笔身是已经用掉的额度，笔锋散开的那几根是还没花的。

为什么是螺旋而不是进度条。进度条是一根线，而 leeway 的图标如果画成进度条，就是在**复刻自己
窗口里的一个 UI 组件**——Apple 的 HIG 恰好明确禁止这个（"prefer illustrations to photos and
**avoid replicating UI components**"）。第一版做了四个进度条方案，全被这条规则否掉，不是品味问题，
是规则问题。把线盘起来则说出了进度条说不出的一半：**额度会转回来，会重置，会周期**——这正是
leeway 探测的核心。而进度条本身就是一根线，所以螺旋不是换了个题材，是同一个元素做拓扑变换。

「尾」这个谐音是用户提的，它和产品语义严丝合缝：尾巴的长度＝还没被花掉的长度。

## 2. macOS 图标的硬契约

- 1024×1024 方图，**超椭圆本体直接烘进像素**，四角透明留白。Apple 的网格是 824 的 squircle
  居中放在 1024 里，角指数 **n=5**（不是圆角矩形）。
- `mygo` 的 `pngToICNS`（`cmd/mygo/icon.go`）只是把图缩到 icns 的各档
  （`icp4 16 / icp5 32 / ic12 64 / ic07 128 / ic13 256 / ic14 512 / ic10 1024`），
  **它不做任何遮罩**。所以 squircle 必须由生成器自己烘进去。
- 超椭圆的半径**不是常数**：轴线上 412px，45° 方向反而涨到 **507px**（n=5 让它比圆更「方」）。
  约束取最紧的那处，也就是**轴线上的 412**。

## 3. 半径预算是算术，不是口味

第一版纯靠代码画，笔身能做多粗是被半径预算锁死的——先解方程再画，能省掉一整轮无用候选。

外缘半径 ≈ `R1 + WIDTH/2`，必须留在 412 以内（实用值取 **380**，留余量）。圈数 N 决定相邻两圈的
间距 `pitch = (R1 − R0)/N`，而 `gap = pitch − WIDTH` 是两圈之间能看见的缝。联立、令中心孔半径
h≈30、要求 gap ≥ 54：

```
WIDTH ≤ (350 − 54N) / (1 + N)
```

| 圈数 N | 笔身上限 | 占画布 |
|---|---|---|
| 1.0 | 148 | 14.5% |
| 1.1 | 145 | 14.2% |
| 1.2 | 130 | 12.7% |
| 1.4 | 114 | 11.2% |
| 1.6 | 101 | 9.9% |

**结论很反直觉但很重要：想画粗，就得少绕圈。** 把圈数从 1.6 降到 1.1，笔身允许从 101 涨到 145，
粗了 44%。最终取 **N=1.10 / WIDTH=145**：1.6 圈在 16px 会糊成一朵实心玫瑰，粗笔身换来的才是
小尺寸下可读的轮廓。

同一轮还量出一个更基础的问题：第一版图形的最大半径只有 **265px**，只占可用空间（412）的 64%——
它不只是线细，是**整个图形就小**。

## 4. 第一版：纯代码画，以及两个真 bug

### 4.1 线宽必须画成多边形，不能用 `ImageDraw.line`

`ImageDraw.line` 画一条 900 点的折线、宽度 384px，在 4096 画布上每段只有 12px 长，于是线段互相
自交、填充出**空洞**，底下那层浅紫透上来，看起来像放射状条纹。

正解是把笔触渲染成**两条偏移曲线围成的精确闭合多边形**（`band()`）：外缘点 + 端头半圆 + 内缘反向 +
起始半圆。数学上干净，没有洞。顺带一提，那次的「放射条纹」用户反而觉得像毛发、要求保留——但它是
缺陷不是设计，所以保留的是它的**观感**（后来的飞白纹理），不是它的成因。

### 4.2 端头半圆的圆心角

`band()` 的端头要补一个半圆把内外两条边封上。第一版写的是 `arc(..., a + pi/2, a - pi/2)`——这是
**以 `a` 为中心**的半个圆盘，连接的是左右两个切线极点，根本没接到内缘和外缘。多边形在端头自我
交叠，PIL 按奇偶规则填充，**在每个线头的端部咬掉一个半圆缺口**。用户放大截图圈出来问「这几个缺口
是啥」，我才发现。正解是从**外缘**（`a`）经切线扫到**内缘**（`a+π`）：

```python
arc(x1, y1, h1, a1, a1 + pi)              # 端头，鼓出去
arc(x0, y0, h0, a0 + pi, a0 + 2*pi)       # 起头，往回鼓
```

`capsule()` 里同样的半圆写法是对的，所以只有螺旋主体中招——**同一类几何写两遍，就有一处会错。**

### 4.3 居中要量对东西

纯代码版的 `mark()` 只拿**笔身本体**量 ink bbox 来居中。墨点是甩出去的、散毛是拖出来的，把它们
算进去，一个偏远的墨点就能把整个螺旋拽偏。这个决定是在用户指出「你这个改的位置不居中」之后做的。

### 4.4 其他

- 4x 超采样（4096 → 1024 LANCZOS），这是边缘干净的主因。
- 盘面是**一条干净的垂直渐变**，没有发光、没有倒角。中途我加过一团左上角的柔光，后来删了——
  那正是我自己批评生成图时用的词「没有动机的柔光」。
- 墨点用固定种子的伪随机。图标是构建产物，不能每次生成都不一样。
- 墨点沿**旋转的切线方向**甩出，越远越小越散——这是「力量感」的来源，均匀撒开就只是噪点。

## 5. 笔触交给大模型

### 5.1 分工

模型擅长**表面质感**，不擅长**构图、几何、居中、比例**。这一轮的结论是把两边分开：

- **笔触表面**（飞白、散毛、甩出的火花）来自 `resources/icon-brush.png`，一张模型渲染。
  手写代码画出的笔触**形状**像干笔，但**行为**不像：丝痕是等距的梳子，毛是规整的扇子。
- **盘面、超椭圆、配色、摆放**全部留在代码里。生成的图只要笔触本身：纯白笔触 + 纯黑底，方图。

### 5.2 brief 怎么写

- **把「不要什么」写死。** 不点名禁止，模型一定会加：发光、雾、灰阶过渡、笔触背后的卡片/面板、
  暗角、边框、黑底上的噪点。第一轮回来的图带着灰底卡片和一圈压缩晕。
- **要什么就用可判定的语言。** 「笔身要粗」没用，写「笔身宽度约为画面宽度的 1/7」「螺旋外径约为
  画面的 72%」「整个图形必须落在直径 72% 的中心圆内，四角干净」。能自查的约束才会被遵守。
- **一次只要 2–4 个备选。** 要 12 个的后果是模型把预算烧在数量上，每个都不够改。
- **一次只让它干一件事。** 两次让它「重画质感 + 保存到指定路径」，两次都耗尽轮次、图留在自己的
  session 目录里没保存。让它专心出图，落盘由外面做。
- **给参考图，并且按用途命名。** 用户给的毛笔参考（飞白、墨点）和火花参考（长拖尾）直接决定了成败：
  在给火花图之前，「溅射」一直做成一粒粒圆点，像撒了珠子；给了之后才明白要的是**细长微弯的光丝**。
- **几何参考要标注「只抄形状、别抄风格」。** 不然模型会把平涂的矢量外观一起抄回去。

### 5.3 反复出现的失败模式

| 失败 | 表现 | 对策 |
|---|---|---|
| 太细 | 画成细笔，笔身被拆成并排独立细线 | 明确「一整块实墨，丝痕在内部」；给定量宽度 |
| 太小 | 图形只占画面一半 | 写死「外径约 72%」 |
| 太散 | 溅射撒满画面 | 写死「紧贴笔锋，约一个笔身宽以内」 |
| 偏 | 重心倒向右上角 | 写死「落在中心 72% 圆内，四角干净」 |
| 僵硬 | 粗细均匀的一条带子 | 要求**提按**：起笔细、中段最饱满、收笔甩出 |
| 加料 | 灰底卡片、发光、水印 | 负向清单写死 |

### 5.4 输出契约

要求模型输出**纯白 `#FFFFFF` + 纯黑 `#000000`**，不是审美偏好，是为了后面能直接拿**亮度当遮罩**。
同理要求方图、居中——都是为了接回代码时少做假设。

## 6. 摆放：解出来的，不是量出来的

这是这一轮花时间最多、也最容易想错的一步。**「找图标的视觉中心」不是先量一个中心再挪过去。**
我把几种「中心」都试了一遍，每一种都有它自己的偏法：

| 定义 | 量的是什么 | 怎么偏 |
|---|---|---|
| 外框中心 | 图形的**范围** | 一根飘到角的散毛就能把主体拽走 |
| 质心 / 重心 | 图形的**质量** | 大量淡笔迹累积起来有重量，把主体往笔锋的反方向拉 |
| 螺旋的眼 | 螺旋的**内圈** | 螺旋是**开口**的，内圈和外部连通，洪泛从边界直接灌进去，找到的是鬃毛缝隙里的小孔（实测 7px、61px、124px），不是眼 |
| 切比雪夫中心 | 最长的那一**伸** | 只压最长方向、不管最短方向，主体被推到对角，配平反而变差（实测 spread 1.49 → 1.54） |

**眼睛读的是「伸得有多远」，不是「质量在哪」。** 实测两张候选的径向分布：k1 在 300° 伸到 386px，
对面只有 315px；k2 更极端，393px vs 261px——这就是眼睛读到的「偏右上」，而它们的质心当时正在正中。

所以位置是**解**出来的：

> 遍历所有候选位置，对每个位置找出**最远的那一个像素**（按超椭圆自身半径折算），
> 选让这个「最远」尽量收得回来的位置。

这就是**超椭圆范数下的切比雪夫中心**。它一步同时得到两件事：

- **配平**：伸得远的方向被拉回来；
- **尺寸**：`scale = FILL / 最远比值`，图形自动做到「再大一点就会被切」为止。

——这正是为什么尺寸不该单独猜。先用「质心居中」再用「目标半径缩放」要调两个旋钮，而这两个量本来
就是同一个数的两面。

两个细节：

- **按超椭圆自身半径折算，而不是欧氏距离。** n=5 的 squircle 在 45° 方向能到 507px、轴线上只有
  412px，用圆去套会白白浪费四个角的空间。
- **取 99.5 分位而不是严格最大值**，免得一粒游离的墨点决定整个版式。放过的这几个像素是最淡的，
  合成时再裁掉（见 §6.1）。

实测：k1/k2 解得 scale 0.804 / 0.820，`worst ratio` 1.119 / 1.097。

### 6.1 两个合成期的 bug

**超椭圆半径公式的指数写错了。** 参数化 `x = a|cos t|^0.4, y = a|sin t|^0.4` 下，极角满足
`tan θ = |tan t|^0.4`，反解应为 `|tan t| = |tan θ|^2.5`。我写成了 `2.5/2 = 1.25`。这个错很安静：
它在轴线上和 45° 处**是精确的**（那两个地方 `tan θ ∈ {0,1}`），只在中间角度错，最多**高估 35px**
（20° 处）。所以早先那句「没有墨迹落在超椭圆外」是**碰巧没切到**，不是算对了。

| 角度 | 真实半径 | exp=1.25 | 误差 | exp=2.5 | 误差 |
|---|---|---|---|---|---|
| 0° | 412 | 412.0 | 0 | 412.0 | 0 |
| 20° | 439 | 473.8 | **+35** | 437.9 | −0.7 |
| 45° | 507 | 507.2 | +0.2 | 507.2 | +0.2 |
| 70° | 439 | 473.8 | **+35** | 437.9 | −0.7 |
| 90° | 412 | 412.0 | 0 | 412.0 | 0 |

**合成时没有裁剪，墨迹漏到身体外面。** 允许 0.5% 溢出是一回事，`alpha_composite` 在盘面透明的
地方**会保留墨迹自身的不透明度**是另一回事——两者一叠，图标圆角外面就有了白色碎屑（实测 114 个
像素，最大超出 2.2%）。修法是在合成**之前**把墨迹裁到超椭圆内；裁完溢出降到 2px（抗锯齿级别）。

### 6.2 尺度：可见墨迹才参与求解

笔锋最外端的发丝在源图里本来就快淡没了，提上来后几乎不可见。按「所有墨迹」求缩放，等于为了迁就
看不见的尖端把整个图形缩小 41%。改成只按**可见墨迹**（alpha ≥ 40）求解，看不见的尖端让它自然
消失在边缘——k1 的缩放因此从 0.612 涨到 0.804。

## 7. 校验工具，以及它们的**局限**

三个工具都在 `build/icon-work/`，都是设计无关的：`eval.py`（16px/32px 覆盖率、盘面平整度、边缘软度）、
`silhouette.py`（丢掉颜色糊成剪影）、`hero.py`（明暗卡片 + 放大到 32/16px）。

**但它们是找缺陷的，不是判品味的。** 两个反例必须记住：

- 拿同一套指标去量 Pulse 的图标（设计标杆），它是 16px 7.8% / 32px 9.5% / 平整度 40.4 / 软边 87.7%——
  **每一项都比我们差**，但人家设计得更好。
- 刻线版（细密丝线）的 16px 覆盖率是 **14.1%**，笔锋版是 **10.5%**——覆盖率更高，但剪影明显更糊。
  **覆盖率 ≠ 可读性。**
- `silhouette.py` 的阈值 120 是按实心图形标定的，对刻线/细笔**会漏检**。刻线版在小尺寸下剪影发白，
  但它的 16px 覆盖率有 19.1%，是能看见的。**不能只凭剪影就断言细笔在 16px 会消失。**

## 8. 窗口里那个标记

窗口标题栏里的标记（`internal/gui/icons.go` 的 `iconApp`）**和应用图标是同一个**。这顺手修掉了一处
不一致：它原本是**三条递减的横线**，也就是一条配额条——正是 §1 判定标记不能当的东西，而窗口自己下面
那一行就在画真的配额条。同一个窗口里，图标说「螺旋」、标题栏说「进度条」，是两句话。

**但「同一个」不是靠画得像，是靠不画。** 第一版是手写的：同样的起点角、挑一个圈数、挑一个笔宽，对着
图标用眼睛调。调了两轮都不像——

- 先嫌它「偏小偏瘦」，把占框和笔宽都加上去；
- 加完还是不像：16px 下图标读作**一块实心风车，中间只有一条缝**，手写的读作**一条细线描的「6」**。

决定你看到哪一个的那个量，是**笔宽对圈距**，而它是我在「圈数 / 占框 / 笔宽」之外**没意识到要调的
第四个旋钮**。图标的笔宽 145 落在圈距 (307−102)/1.10 = 186 上，占 **78%**，只剩 41 单位是缝；我写的
那版是 3.0 落在 6.2 上，**48%**——那不是「同一支笔缠成的螺旋」，那是一条螺旋的线稿。三个旋钮凑一个
比值，就是凑不准。

所以这一版**不画**：读 `resources/icon.png`，取墨迹，**把轮廓矢量化**。标题栏的标记**就是图标自己的
剪影**，结构上不可能跑偏；换图标、重跑脚本，两边自动重新一致。

只剩一个判断：**在多大尺寸上描**。16px 描出来是个八边形；128px 会把每一根飞白都收进来，而它们在 16px
下就是泥。取 **64px**——那里墨块还完整、尾还是**一笔**。描完按面积滤掉碎点、Douglas-Peucker 化简到
46 个点，再放进 24 视框的 0.86。

结果用墨占比验证，不信眼睛：图标 16px 是 **38.8%**、32px 是 **41.0%**，标记是 **41.0%**。中间有一轮我
肉眼觉得「还是细」，其实是对比图裁了 28px 而不是标记自己的 16px 框，把它画小了——**先量，再信眼睛**。

**为什么不用位图。** 直接把 `icon.png` 放进标题栏，就是在字标旁边又摆一个紫色方圆瓷砖——那是第二个
应用图标，不是标记。单色位图则要把颜色烤死，而 MyGo 的 `ui.Image` **不能染色**，就得明暗主题各出一张。
用 `fill="currentColor"` 的路径，主题自动跟，任何尺寸都不糊。

**别拿外部预览来选型。** 我用 PIL 按同样参数缩到 15px 预览，觉得不错；同一组参数放进 MyGo 自己的光栅
器渲染，明显更糊——两者的降采样、抗锯齿和定位都不同。教训：**判断的对象必须是最终渲染它的那个引擎**；
它的推论是，**能用「是」的地方，不要用「像」**。

路径由 [`resources/icon-glyph.py`](../resources/icon-glyph.py) 生成（marching squares 描轮廓、Douglas-Peucker
化简、按面积滤碎点），输出与 `icons.go` 里那段逐字符相同。

## 9. 教训

1. **先查规则，再谈品味。** 前四个方案死于 HIG 的一条明文禁止，不是死于审美。先读约束能省一整轮。
2. **「测量中心」这个提法本身就是错的。** 一个不对称的图形没有唯一中心，每个定义都有偏法；
   应该直接**解**出让最远墨迹最收得回来的位置。位置和尺寸是同一个数的两面，要一起解。
3. **眼睛读的是范围，不是质量。** 质心在正中而看起来还是偏，因为读的是「伸得多远」。
4. **几何先解算术。** 「想画粗就少绕圈」这种反直觉结论，画之前算出来；画之后才发现就浪费一轮。
5. **自己会犯自己刚批评过的错。** 我批评生成图「没有动机的柔光」，转头在自己的盘面上加了一团。
6. **同一段几何写两遍，必有一处错。** 端头半圆的 bug 就藏在「螺旋主体」和「`capsule`」两份实现之间。
7. **指数类的小错误很安静。** `squircle_radius` 的指数在轴线和 45° 处是精确的，只在中间错——
   于是「验证通过」变成了巧合。**要拿真值（遮罩本身）逐点对照，不要只测几个「好记」的角度。**
8. **模型的产物要当外部输入对待。** 背景、居中、比例、色值都不能假设，全都要量、要减、要解。
9. **合成要显式裁剪。** 「允许少量溢出」和「透明背景会保留墨迹不透明度」叠在一起，就是身体外面的碎屑。
10. **让模型一次只干一件事。** 又要重画又要落盘，两次都耗尽轮次、什么都没存下来。
11. **随机必须可复现。** 固定种子，否则图标不是构建产物。
12. **数值指标只能证伪，不能择优。** 它告诉你哪里坏了，不告诉你哪个美。
13. **能用「是」的地方，不要用「像」。** 手写一个「像图标」的螺旋，调了两轮都不像；把图标的轮廓描下来，
    它**就是**图标。参数越多，靠眼睛凑准的概率越低——当「像」调不动的时候，换一条能直接「是」的路。
14. **先量，再信眼睛。** 我肉眼觉得标记「还是细」，一量墨占比是 41.0%，和图标的 41.0% 一样——错的是我
    的对比图裁错了区域。眼睛会被参照系骗，指标不会；但反过来，指标也不能替你判断美（第 12 条）。

## 10. 重做一次的话

```sh
python3 resources/icon.py                 # 从 icon-brush.png 生成 icon.png（Pillow + numpy）
python3 resources/icon-glyph.py           # 从 icon.png 描出标题栏那段 SVG 路径（Pillow + numpy）
go run github.com/egoist/mygo/cmd/mygo@v0.3.4 build   # 打 .app / .dmg，顺带出 icns
```

顺序：

1. 先解半径预算，定圈数与笔身（§3）；
2. 笔触用模型渲染（§5），只要白墨黑底、方图；
3. 盘面在代码里画：垂直渐变 + 烘进 824/指数 5 的超椭圆，四角透明（§2、§4.4）；
4. **摆放用切比雪夫解**：超椭圆范数、可见墨迹、99.5 分位、`scale = FILL / 最远比值`（§6）；
5. 合成**前**把墨迹裁到超椭圆内（§6.1）；
6. 4x 超采样后缩放；
7. 用剪影测试在 64/32/16 各看一遍——**并且记住它只证伪不择优**（§7）；
8. 标题栏标记**从 icon.png 描**，不要另画一个（§8）：64px 描、按面积滤碎点、化简、放进 24 视框。
