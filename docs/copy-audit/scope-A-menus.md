# 范围 A：窗口外壳与菜单 —— 面向用户的中文文案清点与改写建议

- 清点对象：`internal/gui/view.go`（macOS 应用菜单、标题栏、左侧导航、账号行操作菜单与登录菜单）、
  `internal/gui/page_provider.go`（页头与「操作」菜单）、`internal/gui/page_matrix.go`（列菜单）。
- 方法：只读代码判断控件与功能，原文案逐字照抄（含 `…`、全角括号、空格）。范围边缘的条目（页头按钮、
  矩阵单元格状态字）也在表内，但备注里标明「范围边缘」，便于与其他范围交叉核对。
- 改写建议遵循 `docs/copy-audit/glossary-draft.md`（术语草案）已给出的方向：provider→服务商、
  探测→查询、key/API key→密钥、会话文件→登录文件、官方 CLI/客户端→官方工具。与草案不一致处都在备注或
  不确定清单里写明。
- 全文不含任何密钥、token、cookie 内容；表中出现的 `~/.codex/auth.json` 等只在源码原文中。

## 既定约定（摘自 docs）

`docs/GUI.md` 里能当约束用的既有命名 / 文案约定：

- **语言与专名**（`docs/GUI.md:364`）：界面文案中文；provider / 窗口名保持 registry 里的原文。
- **「复制 JSON」是契约名**（`docs/GUI.md:365`）：不显示密钥内容，只显示凭据来源；`复制 JSON` 与 CLI 的
  `usage --json` 同一份契约。
- **两个凭据按钮名是规定**（`docs/GUI.md:239-241`）：官方 CLI 能登录的（cursor / grok / codex / kimi）
  按钮写「登录」，只有 key 用来查额度 / 余额的（deepseek / opencode-go / commandcode）写「配置 key」；
  菜单里只出现这家真读的凭据。
- **「让本机用它」的出现条件**（`docs/GUI.md:241-244`，`docs/GUI.md:7-8`）：只有本机有官方客户端
  （cursor / grok / kimi）且这个账号有能写回的会话时才出现；codex 明确不写 `~/.codex`，key 类不出现。
- **时间与路径按中文说**（`docs/GUI.md:124-126`）：倒计时写「2 天 3 小时后重置」而不是 `2d 03h`；路径走
  `shortenPath()`，文件名永远看得见。
- **同一句话用词一致**（`docs/GUI.md:283`）：用满预测同一句出现在总览主角卡、provider 页窗口行、历史行，
  用词一致。
- **「未配置」是共用概念名**（`docs/GUI.md:186-193`）：未配置的几家共用一行、共用一个「去设置」按钮，
  不再重复「未配置」这句话。
- **失败行主语是应用自己**（`docs/GUI.md:211-213`）：库的原文进 tooltip，窗口只写自己的句子。
- **侧栏分组与文案**（`docs/GUI.md:253`、`docs/GUI.md:137`、`docs/GUI.md:135-136`）：底部「数据」分组
  （历史、关于），上面「监控」分组（总览 + 每个 provider）；一家都没配时写「配置过的 provider 会出现在
  这里」；行尾数字是订阅数，一家也要写。
- **关窗即退出**（`docs/GUI.md:363`）：当前只有窗口进程，没有菜单栏常驻。
- **标题栏词标是墨色**（`docs/GUI.md:98`）：标记画的就是应用图标本身，和 `"leeway"` 说的是同一件事。

`docs/UI-EXEMPLARS.md`：通篇是视觉与工程技法（令牌投射、对比度断言、密度乘数、动效词表、命中与渲染
分离），**没有**面向用户的文案或命名约定，对本次改写没有直接约束；唯一可迁移的是「同类控件共用一套
形状 / 尺寸」，对应到文案就是「同类控件共用一套词」。

另：同目录的 `docs/copy-audit/glossary-draft.md` 是本次并行产出的术语草案，本表建议已尽量与它对齐；
凡与它冲突或需要它先拍板的，列在下面。

## 不确定清单

1. **「复制 JSON」要不要改名**：`docs/GUI.md:365` 把它与 CLI `usage --json` 的契约绑在一起，README 与
   `leeway help` 也用 JSON。改成「复制数据」更易懂，但会割裂与 CLI 的对应关系。两条路：统一写成
   「复制 JSON」（改掉「复制当前 JSON」这一处异名，改动最小），或全窗口 + 文档一起改「复制数据」。
   建议由产品层拍板，本表暂按草案写「复制数据」。
2. **「让本机用它」定名**：动作是「把账号的登录状态写给本机官方工具」，4 字装不下；草案建议「同步到
   官方工具」（6 字）。这个名字还被 `page_provider.go:92` 的说明句和 `prompt.go:267` 的确认标题直接
   引用，改名是三处联动。属产品专有概念，建议单独定名并写进文档。
3. **「手动刷新」怎么摆进间隔菜单**：同组其余项描述「多久一次」，这项描述模式；4 字方案（「只手动」）
   会丢掉「刷新」，5 字（「不自动刷新」）超上限。需要先定这个菜单项的命名规则是「模式」还是「频率」。
4. **「打开配置目录」**：真实行为是「在访达里显示 config.json」，诚实的名字 6 字（在访达中显示 / 显示
   配置文件）超出 4 字上限；坚持 2–4 字只能写「显示文件」之类，含义有损。
5. **「退出登录」与 CLI 冲突**：`leeway logout`、README、`leeway help` 都用「退出登录」，而 CLI 行为是
   契约（`AGENTS.md` 硬约束）。只改窗口会造成 CLI 与窗口两套词。是否连 CLI 一起改需产品层决定。
6. **「配置 key」/「API key」/「密钥」的统一**：草案建议统一「API 密钥」，但 CLI 帮助、README、设置页
   都写 key；且「API 密钥」是 5 字符，4 字上限下只能写「配置密钥」/「删除密钥」。需要定一套。
7. **「用官方 CLI 登录…」**：草案建议「官方工具」，但 `leeway login cursor` 走的确实就是 CLI，
   README / `docs/PROVIDER-FETCH.md` 都用 CLI；改窗口词会与文档不一致。
8. **两条 cookie 菜单怎么区分**：「从浏览器导入 cookie…」与「粘贴 cookie header…」改成「登录状态」
   之后会变得难以区分（都像「导入登录状态」）；需要先定这两条的区别怎么用一句话说清，再定名。
9. **「探测」是否全窗口统一成「查询」**：本块只有 `view.go:242/244` 两处，另有
   `page_overview.go:676`、`app.go:306/341`、`settingsview.go:131`（通知开关）、`page_provider.go:66`
   等；只改本块会造成同一动作两种词。建议作为跨范围的统一决定，一次改完。
10. **「数据」分组名**：分组里「关于」不是数据。改名（如「更多」）只改文案不改结构；要真正合理，得把
    「关于」移出该分组（结构改动，超出文案范围）。
11. **菜单栏中文化的程度**：本块能直接改的只有自定义项（文件 / 刷新 / 复制 / 设置 / 关闭窗口）；「编辑」
    「窗口」及系统项（服务、隐藏、退出）要自己写 `Submenu` + 每项 `Label`，回归面较大，且 macOS 习惯
    常留英文。需要决定是否整栏中文化，以及系统项是否保留英文。
12. **「更新于 12 分钟前」改成什么词**：若改成「12 分钟前查询」，就绑定了草案的「查询」；若草案最终
    选别的词（如「读取」），这里要跟着改。

## 小结

这一块的文案问题集中在三处：**菜单栏中英混排**——只有「文件」及其子项是中文，应用菜单、`Edit`、
`Window` 以及 `Close Window` 全部由 MyGo 角色按英文生成，同一个菜单栏两种语言；**同一个东西几个名字**
——同一份 JSON 的复制动作在菜单里叫「复制 JSON」、在账号菜单和「操作」菜单里叫「复制当前 JSON」，
设置入口在菜单里写「设置…」、在标题栏写「设置」，同一个空状态标题栏说「没有启用的 provider」、
侧栏说「配置过的 provider 会出现在这里」；**内部术语漏进界面**——「provider」「探测中 / 探测失败」
「cookie header」「会话文件」「CLI」都是实现词，而全窗口同一个刷新动作在状态文字里却换了名字。
命名整体上是「短词一致、长句各写各的」：总览 / 历史 / 关于 / 刷新 / 账号 / 未配置这些两字词全窗口
统一得很好（还都被测试钉住），但一旦是句子（空状态、失败状态、说明句）就没有共用词表，同一状态在
不同页面各写一句，这也正是需要先有一份术语表再动手的原因。
